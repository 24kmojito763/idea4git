# 0.2 高级 Git 工作流

本版新增下面八项可操作的 Qt 界面，复用系统 Git。下面的“支持”指列出的具体流程，不代表覆盖该 Git 命令全部参数。Linux + Git 2.43 已验证；高级命令要求 Git 2.38+。Windows、远程认证和复杂 hooks 仍待实机验收。

## 0. 文件选择提交与推送

- 提交面板的复选框只表示是否包含在本次提交；勾选/取消勾选不会直接修改 Git 索引。冲突文件不能勾选。
- 提交时应用只对所选路径运行 `git add -A -- <路径>`，随后运行 `git commit --only ... -- <路径>`。既有暂存区中未选中的路径会留在暂存区，不会夹带进本次提交；包含空格、换行、非 ASCII 或 pathspec 特殊字符的路径按字面路径传递。
- **提交并推送**仅在提交成功后打开推送预览。预览可选择远程和目标分支，查看待推送提交及所选提交的变更文件；文件右键会在主编辑区打开带增删颜色的差异。
- 待推送提交基于本地 `refs/remotes` 跟踪引用计算，最多显示 500 条；若远程跟踪引用尚未更新，预览可能与服务器当前状态不同，推送前可先 Fetch。推送使用显式 `HEAD:refs/heads/<目标分支>` refspec，不添加强制参数。
- **管理远程**只写当前仓库配置，显示 URL 时遮蔽用户信息；HTTP(S) URL 不允许带用户名/密码、查询参数或 token。**Git 凭据**调用 Git Credential Manager 提供 GitHub 浏览器登录、账号退出及 PAT 保存/移除。PAT 仅经标准输入交给凭据管理器，不进入命令参数、应用设置或远程 URL。

## 1. 任意两版本比较

入口：**Git → 比较任意两个版本**。也可在提交历史中多选两行后右键比较。

- 左右版本支持本地/远程分支、轻量/附注标签、完整/缩写提交哈希和 `HEAD~N` 等提交表达式。
- 先通过 `rev-parse --verify --end-of-options <版本>^{commit}` 解析为固定哈希，再生成 NUL 分隔的增删改/重命名列表；不拼接 shell 命令。
- 只按选择加载文件：左右只读全文、增删行底色，以及统一补丁；可交换左右版本。比较只读，不写工作区或暂存区。
- 二进制、非 UTF-8、超过 5 MiB 的全文不内联编辑，统一补丁仍显示 Git 可输出的差异/二进制信息。文件列表最多显示前 5000 项，候选引用最多加载 1000 条；未列出的引用可手工输入。

## 2. 三方冲突解决

入口：**Git → 三方冲突解决**，或顶部进行中操作提示条。多文件冲突先选择一个文件，逐个解决。

- 上方分别显示 Git 索引阶段 2（ours）、1（base）、3（theirs），下方是可编辑 result。可以使用任一侧全文，或手动组合结果。
- rebase 时 ours 是已变基到的上游/当前结果，theirs 是正在重放的提交；窗口明确提示，不将二者误标成普通 merge 的“我的/他人的分支”。
- 修改/删除、双方新增等可能缺失阶段。选择缺失的一侧表示删除；保存删除结果前再次确认。
- **保存结果**只原子写入/删除工作区文件，保留冲突索引。**暂存并标记已解决**才调用 `git add -A -- <路径>` 清除 unmerged 阶段；两步不自动合并，更不自动继续或提交。
- 保存/暂存前核验索引阶段和工作区快照，检测外部变化时拒绝覆盖。结果尚未保存时关闭会询问；保留冲突标记时不启用内置暂存按钮。
- 当前支持不超过 5 MiB 的 UTF-8 普通文本，保留 BOM/换行方式。二进制、非 UTF-8、符号链接、子模块或不安全路径只读，需外部工具；不是逐块自动合并器。

## 3. Merge

入口：**Git → 合并**。预览目标后勾选确认再执行。

支持按 Git 配置合并、`--no-ff`、`--ff-only`、`--squash`。Squash 只准备暂存区，之后使用普通提交按钮。要求已跟踪文件的工作区/索引干净，无其他进行中流程；不会自动 stash。发生冲突后显示 **解决冲突 / 继续 / 中止**。继续使用 Git 已有合并提交信息，不启动终端编辑器；中止调用原生 `merge --abort`，不使用 hard reset 兜底。

## 4. Rebase

入口：**Git → 变基**，选择新的上游版本。

支持普通非交互式变基和可选 `--rebase-merges`。使用 `--no-autostash --no-update-refs`，不自动隐藏修改，也不顺带更新其他分支引用。提交哈希会改变，预览明确提示已发布历史对协作者的影响；不自动推送。

中断后提供原生 **continue / abort / skip**：继续前要求所有冲突已解决并暂存；跳过会丢弃当前重放提交，需确认；中止尝试恢复开始前状态，需确认。交互式 todo 编辑、reword/squash/fixup 和自定义 `--onto` 选择器未实现。

## 5. Cherry-pick

入口：Git 菜单，或提交历史右键 **Cherry-pick**。

复制一个指定提交到当前分支；支持合并提交的明确 mainline 父编号。普通提交必须不指定 mainline；合并提交未指定或超出有效父编号时拒绝执行，不猜测父提交。冲突中断后提供继续、中止和跳过。当前界面一次选一个提交，不解析/批量执行提交范围。

## 6. Revert

入口：Git 菜单，或历史右键 **Revert**。

创建一个新的反向提交，保留原历史；合并提交也必须选择 mainline。采用 Git 原生 `revert --no-edit`，冲突后可继续、中止或跳过。当前一次操作一个提交，不支持多提交范围批处理。

## 7. Reset

入口：Git 菜单，或历史右键 **重置**。

| 模式 | HEAD/分支 | 暂存区 | 工作区 |
| --- | --- | --- | --- |
| Soft | 移到目标 | 保留 | 保留 |
| Mixed（默认） | 移到目标 | 重置到目标，原暂存选择丢失 | 保留 |
| Hard | 移到目标 | 重置到目标 | 丢弃受影响的修改；妨碍写入目标版本的未跟踪文件/目录也可能被 Git 删除 |

三个模式都先显示仓库、分支、当前 HEAD、完整目标哈希与后果，并要求勾选确认。Hard 还必须输入 **RESET**。执行前重新核验 HEAD/分支及进行中操作；目标已固定为哈希。未提交内容不能依靠 reflog 恢复，不承诺自动备份或撤销。存在其他进行中流程时，应先明确完成/中止该流程，而非直接 reset。

## 8. Stash

入口：**Git → Stash 管理**。

- Push：填写说明；可包含未跟踪文件（不包含忽略文件），可保留当前暂存区。仓库需已有首次提交，且无冲突或其他进行中流程。
- List / Show：显示引用、完整提交的缩写和消息；按所选 stash 加载包含未跟踪内容的补丁。
- Apply：应用后保留记录；可勾选 `--index` 恢复暂存选择。
- Pop：按不可变 stash 哈希应用，**仅成功后**再查找并删除对应记录。冲突保留原记录，不按过时的 `stash@{N}` 应用另一个 stash。
- Drop：展示引用、哈希与消息，需输入 **DROP**；本界面不提供删除后的恢复入口。
- stash 应用发生冲突时可进入同一个三方解决器，但 Git stash 没有专门的 `--continue/--abort`。解决后按正常流程提交；原 stash 由用户确认是否删除，不伪造 Git 恢复语义。

暂不提供 stash branch、clear-all 和按块 stash。若外部进程同时改写同一 stash reflog，无法保证跨多条 Git CLI 的事务隔离；应用会重新查找哈希并在丢失/重复引用时拒绝删除，应避免其他工具同时写入该仓库。

## 共同约束

- 编辑器有未保存标签时，拒绝启动会改动工作区的高级操作；用户需先保存或关闭标签。操作结束后重载未修改的已打开标签，移除已删除文件标签，不覆盖未保存缓冲区。
- 新的 merge/rebase/cherry-pick/revert 要求已跟踪状态干净；Git 自己继续保护被覆盖的未跟踪文件，不自动使用 force。
- 所有 Git 工作串行异步执行；可取消，写入/继续命令超时 120 秒。取消进程不等于回滚，可能留下已生效结果或进行中流程，需要刷新并选择继续/中止。
- 通过 `rev-parse --absolute-git-dir` 定位当前工作树的元数据目录，仅只读检测状态；实际继续/中止均交给 Git，不直接修改 `.git`。未知 sequencer（例如 `git am`）不会被当成 rebase 中止。
- 写操作的子进程局部设置 `GIT_EDITOR=true`，继续时沿用 Git 现有提交信息，避免终端编辑器阻塞。Linux 本机已验证；Windows 的 Git/无操作编辑器可执行程序发现仍需专项验证。
- 原有 Git 配置、hooks、签名与凭据助手保留；外部进程不与应用共享事务锁，因此预览复核不能替代避免并发写仓库的操作约定。

## 验收

`advanced-git-workflows` 在独立临时仓库验证：标签/哈希/特殊路径版本比较与重命名；merge 的快进/no-ff/squash；三方阶段内容、保存/暂存分离、外部更改保护、修改/删除冲突；rebase/cherry-pick/revert 的冲突继续/中止/跳过；mainline 校验；三种 reset；过期计划拒绝；stash push/show/apply/pop/drop、保留/恢复暂存选择、冲突保留记录；取消排队写入后的回调完成；worktree 独立状态与含中文/换行的仓库路径。

`advanced-git-ui` 操作真实 Qt 控件验证：左右全文与补丁/行标记；三方源和结果保存/暂存按钮；关闭未保存结果确认；五种命令表单与 Hard 的双重确认；stash push/apply/pop/drop；主窗口发现 merge 中断、刷新冲突状态并继续。截图输出方式见 README。测试不访问远程网络、不写用户全局 Git 配置、不改原项目历史。
